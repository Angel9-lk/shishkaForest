# Анализ сетевого трафика и обнаружение аномалий

Проект посвящён загрузке и анализу сетевых потоков из набора CICIDS2017-DOS. Данные хранятся в SQLite, нормализуются по справочникам IP-адресов, протоколов и меток атак, а затем анализируются SQL-запросами. Для поиска подозрительных потоков используется межквартильный размах (IQR).

## Модель данных

Основная таблица `traffic_flows` содержит признаки сетевых потоков: IP-адреса и порты источника/назначения, протокол, время наблюдения, длительность потока, количество и размеры пакетов, интервалы между пакетами, TCP-флаги и метку класса.

Справочники:

- `ip_addresses` — IP-адреса источника и назначения;
- `protocols` — номера и названия протоколов;
- `attack_labels` — метки атак и признак benign;
- `feature_statistics` — квартильная статистика признаков;
- `whitelisted_ips` — доверенные IP-адреса;
- `traffic_flows` — нормализованные сетевые потоки;
- `staging_traffic` — промежуточная таблица загрузки.

В текущей базе проверено: 110 573 записи в `traffic_flows`, 110 573 записи в `staging_traffic`, 4 759 IP-адресов, 4 протокола, 6 меток атак и 72 статистических признака.

## Как выполняется обработка

1. Исходные строки загружаются во временную таблицу `staging_clean`.
2. Из данных заполняются справочники IP-адресов, протоколов и меток.
3. Потоки переносятся в нормализованную таблицу `traffic_flows` через внешние ключи справочников.
4. Квартильная статистика используется для вычисления верхней границы выброса:

   `upper_bound = Q3 + 1.5 × IQR`

5. Для длительности потока, количества прямых и обратных пакетов рассчитывается балл аномалии.
6. Поток классифицируется как:
   - `Аномалия` — два или более признака вышли за верхнюю границу;
   - `Требует проверки` — один признак вышел за границу;
   - `Норма` — выбросов не обнаружено.

## SQL-запросы

- `Создание базы данных и внесение данных.sql` — создание промежуточной таблицы, заполнение справочников и перенос данных.
- `Поиск аномалий.sql` — поиск выбросов по IQR и формирование `detection_result`.
- `Аналитический запрос №1.sql` — общее число потоков и атак.
- `Аналитический вопрос №2.sql` — активность источников атак и типы атак.
- `INSERT-запросы.sql` — добавление тестовых IP-адресов, доверенного адреса и тестового потока.

## Ограничения

- Данные об IP-адресах представлены в кодированном виде (`encoded_ipv4`), а не в обычной точечной записи.
- SQL-скрипты рассчитаны на существующую схему SQLite и порядок столбцов исходного датасета.
